## What the next tickets must fit around (decisions from T06 not obvious from the spec)

- **Schema changes must be additive.** `db.connect()` runs `CREATE … IF NOT EXISTS`, then adds any column listed in
  `ADDED_COLUMNS` that an older database lacks, then creates `INDEXES` on those columns (`app/db.py`).
  - A new column on an existing table goes in `ADDED_COLUMNS` (and in the CREATE TABLE for fresh databases).
  - A CHECK or constraint can't change in place: use a new table or a new column instead.
  - The real `cms.db` in the main checkout was made before T06 and must keep working.
  - Test pattern: `database_from_before_t06` in `tests/test_t06_revisions_trash.py`.
- **Trash.** `guides.trashed_at IS NOT NULL` means the Guide is in the Trash, and that is separate from status.
  - Every Guide query goes through `_NOT_TRASHED` / `_visible_to` (`app/guides.py`).
  - Any new query over Guides (T07 term usage, T09 per-user Guide counts, the Author pages) must exclude the Trash too.
  - A trashed Guide's slug stays reserved.
- **Revisions** (`revisions` table, one per Guide, `Revision` dataclass in `app/guides.py`) copy a Guide's texts, Hero and Patch.
  - **S1:** the spec says a Revision also carries images and cover. S1 must add them to `revisions`, copy them on
    `open_revision`, and apply them on `publish_revision`.
  - **S1:** `delete_for_good` must also delete the Guide's image files. Its docstring and the #7 comment say images join it later.
  - **T07:** preview warnings for unknown terms belong on the Revision preview too (`preview_page` in
    `app/routes/guides.py` serves both).
- **Review rounds** of a Revision use `kind = 'return'` with `review_rounds.revision_id` set; there is no FK, and Revision ids
  are AUTOINCREMENT so they are never reused. `Guide.returned` counts only rounds with `revision_id IS NULL`.
- **Submission ban** (T09) already blocks Submitting Guides *and* Revisions (`_check_not_banned`). T09 only needs the
  Users page to set the state.
- **Capabilities** (`app/accounts.py`): `manage_trash` was added. Route guards check capabilities, never role names
  (see `trash_manager` in `app/routes/trash.py`, `admin_user` in `app/web.py`).
- **Pending count.** `changes_not_on_site` (`app/publish.py`) unions three sources:
  - Published Guides edited since the last build,
  - `unpublished_since`,
  - `trash_changes_since`, which includes the `removed_guides` table.

  It may overcount, never undercount. T08 Pages and Tournament items will need to feed it the same way.
- **Confirmation pages**: `templates/admin/confirm_delete.html` takes `question`, `consequences`, `button`, `action` and
  `cancel`. Reuse it for any other destructive step (deactivating a user, deleting a Page).
- **Console templates** link with `{{ console_root(request) }}{{ item.console_path }}`. Both `Guide` and `Revision` have
  `console_path`, and Revisions are duck-typed as Guides in the editor, preview and review templates.
