## What the next tickets must fit around (from #25, not obvious from the spec)

- **Times are shown only through `app/times.py`.**
  - `beijing_time` (`2026-10-17 21:05`) and `beijing_date` (`2026-10-18`) are Jinja filters in both the console
    environment (`app/web.py`) and the site environment (`app/publish.py`).
  - Both return `""` for a NULL time.
  - Storage and every comparison stay UTC. The offset is a fixed UTC+8, not `zoneinfo` (see the #25 comment
    for why).
- **`test_no_template_prints_a_stored_time_without_converting_it` scans every template.**
  - It fails on any `{{ … }}` that names a `…_at` field without `|beijing_time` or `|beijing_date`.
  - Name every new timestamp column `…_at` (an image's `created_at`, say), so the scan covers it.
  - `tournament_date` is a calendar date the Admin types. It is not converted.
- **Wide console tables** go in `<div class="scroll">` (`templates/admin/base.html`). A cell holding a title or
  a sentence gets `class="wrap"`, or `.scroll td { white-space: nowrap }` puts it all on one line.
  - The Guide list, Trash, dashboard review queue, Users, Pages, Tournaments and Terms tables already follow this.
- **Displayed times no longer carry milliseconds,** so two changes in the same minute look the same in the
  console. Prove an update happened some other way. `test_publishing_a_revision_replaces_the_guides_content_and_keeps_its_url`
  now checks the content-list order (most recently updated first).
