## What the next tickets must fit around (from T09, not obvious from the spec)

- **Admin-only guards come from `web.requires(capability)`** (`app/web.py`).
  - Make one guard per capability at module level, e.g. `user_manager = requires("manage_users")`, so FastAPI's
    per-request dependency cache recognises it.
  - Each guard is registered in `web.ADMIN_GUARDS`. The test
    `test_an_editor_is_refused_on_every_admin_only_route` (`tests/test_t09_users.py`) walks every router module
    under `app/routes/` and finds the routes guarded by one. A new route behind `requires(...)` is covered
    automatically (rubric D3), with no test edit.
  - A route that refuses *inside its body* (`raise AdminRequired(user)`, as the review pages in
    `app/routes/guides.py` do) is **not** found by that walk. Prefer the dependency.
  - T07 (Game Terms) and T08 (Pages, Tournament items) should guard their routes with `requires(...)`, either with
    an existing capability (`manage_game`) or a new one added to `CAPABILITIES` in `app/accounts.py`.
- **`AdminRequired(user)` now carries the user.** The 403 renders `templates/admin/refused.html` with the console
  navigation.
- **Account changes live in `app/accounts.py`** (user-management section at the bottom).
  - Each change repeats its precondition in its UPDATE (`_update(..., refusal)`, `CHANGED_MEANWHILE`).
  - The last-active-Admin guard is the SQL fragment `_KEEPS_AN_ADMIN`.
  - Follow the same pattern for any new change that a concurrent edit could overwrite.
- **Submission ban:**
  - `accounts.SUBMISSION_BANNED` is both the refusal reason and a notice that `base.html` shows on every console
    page to a banned user.
  - The ban blocks Submit, opening a Revision, and Submitting a Revision.
- **Template globals:** `min_password_length` and `submission_banned` (next to `console_root`, `csrf_token`).
- **Wide tables:** wrap them in `<div class="scroll">` (CSS in `base.html`). On a phone the table then scrolls
  sideways instead of wrapping one character per line. The Users table does this. The Guide list and the Trash
  don't yet.
- **Schema:** `users.last_login_at` was added through `ADDED_COLUMNS`. The test
  `test_a_database_made_before_the_users_page_still_works` shows the pattern for a table that predates a column.
- **Per-user Guide counts:** `guides.counts_by_author` (requires `manage_users`; Trash excluded).
- **Removed:** `accounts.set_state` is gone. Arrange account states in tests with `conftest.add_user(..., state=...)`
  or through the Users page.
- **Known debt, deliberately left (see the #10 comment):**
  - `accounts` and `guides` each have their own `Refused` / `NotAllowed` and `status_for`.
  - The account page counts every Author's Guides just to read one Author's counts.
