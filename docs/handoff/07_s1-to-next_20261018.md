## What #12 must fit around (from S1, not obvious from the spec)

- **No request size limit on uploads.** `app/web.py` `sent_image` reads at most 5 MB + 1 byte from the
  upload, but Starlette has already received and spooled the whole multipart body by then. A hosted console
  needs a body-size cap in front of the app (proxy or middleware). This finding was deferred to #12 in the #11
  comment.
- **Uploaded files live outside the database**, in `settings.media_path()`: `CMS_MEDIA`, else `media/` next to
  `cms.db` (git-ignored). A host needs a persistent disk for both, and backups must cover both.
- **The console serves images itself**, only to someone allowed to edit the owner, via `image_response` in
  `app/web.py`. It answers with `X-Content-Type-Options: nosniff`. Keep that header if a proxy serves `media/`
  directly instead.
  - The routes are `GET …/images/{filename}` under `/admin/guides/{id}`, `/admin/guides/{id}/revision` and
    `/admin/tournaments/{id}`.
  - `media.FILENAME` (`[0-9a-f]{32}\.(png|jpg|webp|gif)`) and an owner check stand in front of every file read.
- **File writes and deletes follow the transaction** through `db.after_commit` (`app/db.py`). Any new code that
  touches `media/` should do the same, so a failed save never leaves the disk and the database out of step.
- **The Site build copies images** into `site/media/`. If 更新网站 runs on the host, that host needs `media/`.
- **Route count** is 23 in the T08 route test (`tests/test_t08_pages_tournaments.py`). New routes change it.
- **Image forms post `multipart/form-data`** (the 上传 button's `formenctype`), and the CSRF token comes from the
  form like every other field. Any CSRF or rate-limit middleware added for #12 must handle multipart bodies.
