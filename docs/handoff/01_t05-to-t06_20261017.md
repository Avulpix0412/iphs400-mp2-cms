## What T06 must fit around (decisions from T05 not obvious from the spec)

- **Review rounds.** Each Return or Unpublish is a row in `review_rounds` (`kind` is `return` or `unpublish`),
  with its notes in `review_notes` (`app/db.py`).
- **"Returned" is derived, not stored.** `Guide.returned` means a Draft with at least one review round.
  It is only correct because a Guide can only go from Submitted or Published back to Draft through a
  Return or Unpublish.
  - **Watch out:** if T06 adds any other route back to Draft (for example, restoring from the Trash), it
    must keep this rule true, or `returned` must become a stored flag.
- **Revisions under review.** The spec says Revisions are Published or Returned like a new Guide, and a
  Returned Revision leaves the live Guide untouched. `return_guide` and `_send_back` (`app/guides.py`)
  only handle Guides today. They will need a Revision path.
- **Race guard.** `_send_back` updates status with `WHERE id = ? AND status = ?` and refuses if no row
  changed. `publish` (T03 code) still reads and then writes with no such guard. That is a known gap,
  deliberately left out of T05.
- **Highlighting.** `highlight(html, latest, earlier)` in `app/rendering.py`:
  - matches quotes ignoring whitespace and formatting, and splits each `<mark>` at the tags it crosses;
  - marks the latest round `<mark>` and earlier rounds `<mark class="earlier">`;
  - is used by the preview only. The Site build must never call it.
  - The preview shows no highlights once a Guide is Published again. The user confirmed this.
- **Dashboard pending count.** `changes_not_on_site` (`app/publish.py`) counts edited Published Guides plus
  Unpublished ones via `guides.unpublished_since`. It may overcount, by design (reasoning is in the #6
  comment). Deleting a Published Guide to the Trash in T06 must also count as a pending change.
- **Permissions.** The `publish_guides` capability also covers Return and Unpublish (`app/accounts.py`).
- **Status codes.** Editors get 403 on their own Guides and 404 on anyone else's, consistent with T03.

## Working conventions confirmed this session

- **Test seams** are fixed by spec #1: Seam 1, the console over HTTP (`client_as`); Seam 2, `render_site`.
  Tests never read database rows.
  - Reuse the helpers in `tests/test_t03_guides.py` (`new_guide`, `act`, `save`, `status_of`) and
    `tests/test_t05_review.py` (`submitted_guide`, `published_guide`, `review`, `preview_of`).
- **Typecheck:** `uvx pyright --pythonpath .venv/bin/python app scripts/seed_demo.py tests/conftest.py tests/test_t0*.py`
- **Tests:** `uv run pytest -q`
- **Before the commit that closes a ticket:** post the `/code-review` findings and how each was resolved as a
  comment on the issue. Revisions made after the review get appended to that same comment.
- **Commits** start `T0N:`. The closing commit ends `Closes #N`. Write the ticket id to `.claude/state/phase`.
- **No new dependencies** without asking the user.
- **PRs** use merge commits (`gh pr merge --merge`). Keep the branch. The repo has no CI checks.
- **Transcripts** (`docs/transcripts/…session_NN…md`, raw JSONL from a SessionEnd hook) and
  `notes/usage-ledger.csv` rows get committed in a separate "Add transcript NN and update usage ledger"
  commit.
  - Scan transcripts for credentials before pushing.
- **The `/browse` (gstack) skill** works for visual checks of local HTML: save a page from a test to a file,
  then `goto file://…`. Dark-mode media emulation is denied, so force it with
  `js "document.documentElement.style.colorScheme='dark'"`.
