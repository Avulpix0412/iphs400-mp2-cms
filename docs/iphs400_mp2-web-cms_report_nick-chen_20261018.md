## 1. What did you build, and which decisions in the grill were yours?

I built a guide website for an online card game the Bazaar, which is a small CMS for Chinese community of the game. I wished to built this website because currently the community have all kinds of guides, mainly on a video app called Bilibili, but do not have any website. Guides on the video platform usually takes the form of uploaders talking over a powerpoint. People are not able to skim during fragmented time or without voice, such as when they are on the bus. Videos also take time to make and it often happens when an uploader wish to make guides about current game, but after the guides was made, the environment of the game has already changed after a balance patch, so I would say people needs this kind of website for better experience. On my site, the uploaders or the streamers are admins, invited writers are editors, and the essential rule is that nothing will goes public until an admin publishes it. The public site is static, in both Chinese and English, and it is on github pages. The spec is issue #1, the work went through from T01 to T09, the image-upload stretch ticket, and four other issues during the process (#15, #18, #25, and #31). 

I basically made every decisions at the grill stage. I wish to make things clear at the very first stage, so my answers to questions are all relatively long. I can talk about a few of them. Claude recommended to mark guides for old patches as they might have been outdated, and I thought that was not very ideal, because balance patch happens so often and it is possible that only one or two cards are changed during one patch. It takes time to finish guides and guide for past version are often still useful if none of the cards mentioned are changed. I also overrode the language design. Claude  suggested Chinese guides can also be listed on the English site with a badge, but I asked for Claude to change to one switch that moves the whole site, so a reader stays in only one language. There are also some small decisions, like I decided that Editors can delete their ow published guides when Claude suggested that they couldn’t, and I also decided that a submission ban did not automatically hide all of the editor’s old guides, because it is not likely that all of the previous guides have problems. Something I told Claude during the grill session became later features. For example, I mentioned that many players have nicknames for heroes, and this become the nickname warning feature done in T07, and also a reviewer should be able to mark the exact passage of a guide when they decided not publish it and send it back to the editor, and this became the quoted review notes in T05.


## 2. Where did the AI drift or invent something, and what caught it?

During the process, Claude made several mistaks and it reported some of them itself, and I also caught some of them. One of the most clear case was in T04 #5 about the site build. Claude put the new public site templates in ‘templates/site/’, but the problem is that the repo’s ‘.gitignore’ already had the line ’site/’ for the build output, and that line matches any folder named ’site’, so the templtes were being ignored. On my own end, everything worked because the files were there. The ‘/code-review’ subagent caught it before the merge : "`.gitignore` line `site/` also ignored `templates/site/`, so the new public-site templates would never be committed and a clean clone's Site build would fail”, and the fix was one character: `/site/`. The most serious problem about this is that the tests didn’t catch it, because they run on my laptop, where the files exist. This was the similar issue that happened again and became #31 when sked Claude to test the README's Run locally steps on a fresh clone, it found that the rubric's judge runs the seed script without `--env-file`, and on a clean clone that fails before any account is created.

Another drift happened in #18. I told Claude that the console templates are not exempt from the root-absolute-path check, but its issue suggested exactly the opposite that "narrow which files the check scans by adding `':(exclude)templates/admin/**'`". I caught it by reading the issue. The cause was `CLAUDE.md`, which said "Published HTML uses relative paths only", and Claude read that literally. I then had the rule changed to "All committed HTML".
